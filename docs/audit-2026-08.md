The codebase is healthy at the foundation — workspace builds, ~1,624 tests green,
engine core disciplined — but carries: (a) a handful of real correctness/robustness
defects concentrated at the web trust boundary and in silent-passthrough engine
code, (b) an information leak affecting both AI fairness and human play,
(c) severe documentation drift (the entire web client is undocumented), and
(d) repo hygiene debt (`main` 540 commits stale).

**Direction chosen:** harden, then ship "play Arcana with a friend" end-to-end.
Research arcs stay frozen (they are cleanly closed as pre-registered negative
results); the named successor research thread is PIMC action distillation, gated
behind the A-2 fix.

## W — arcana-web (trust boundary, robustness, networked play)

- [x] **W-1 (P0)** `/new` with a `MatchConfig` bypasses deck validation: `GameCore::from_match_config` (`arcana-web/src/lib.rs:910-943`) only checks decks are non-empty. An unregistered `CardId` panics inside `instantiate_card_object` (`arcana-core/src/engine.rs:4441`) on the worker thread — after which **every solo endpoint returns 500 until restart** (`run_worker`, `arcana-web/src/main.rs:521-623`). The guard `deck_is_valid` (`main.rs:460`) exists but is applied only to the legacy `deck`/`opponent` fields (`main.rs:600-604`). Fix: validate registry membership + a deck-length cap in `from_match_config`. — **done 2026-08-04, `7f84dad9`.**
- [x] **W-2 (P0)** Same class in matchmaking: `Matches::create`/`join` validate only non-emptiness (`arcana-web/src/matchmaking.rs:451-455, 481-486`). Bogus ids panic the spawned match thread (`spawn_match` → `matchmaking.rs:311-328`); the match dies silently — clients see "the match has ended" with no log. No deck-size upper bound. Fix alongside W-1. — **done 2026-08-04, `7f84dad9`.**
- [x] **W-3 (P0)** Mutex-poisoning cascade: eight sites do `app.matches.lock().unwrap()` (`main.rs:742-1323`); any panic while holding the lock (e.g. the `.expect("spawn match thread")` at `matchmaking.rs:326`) poisons it → every networked handler panics **and the reaper task dies** (`main.rs:1319-1328`), silently disabling stale-match cleanup. Fix: `catch_unwind` / rebuild-on-panic around worker & match threads, or tolerate poisoning (`lock().unwrap_or_else(|e| e.into_inner())`) plus panic containment. — **done 2026-08-04, `d9554f90`.**
- [x] **W-4 (P1)** Seat tokens are the entire networked auth model and are predictable: splitmix64 seeded from a nanosecond timestamp (`Matches::new` seeding at `main.rs:1300`; `next_rand`/`token` at `matchmaking.rs:422-433`), sent as query params on every `/m/*` request including the WebSocket URL (`MatchRef`, `main.rs:121-127`, leaks into logs/history), compared non-constant-time (`matchmaking.rs:413, 535`). Fix: `getrandom`-sourced tokens; move to a header/cookie; constant-time compare. — **done 2026-08-04, `df2d0ac8`.**
- [x] **W-5 (P1)** Persistence is fragile: networked-match persistence is opt-in (`MATCH_STATE_DIR`, `main.rs:1299`), the write is a non-atomic full-transcript `std::fs::write` after every action (`matchmaking.rs:148-156`), corrupt files are silently skipped on load (`matchmaking.rs:340-342`), tokens are persisted in plaintext, lobbies are never persisted, and the solo game is purely in-memory. Fix: write-to-temp + rename; log skipped files; consider making persistence default-on. — **done 2026-08-04, `df2d0ac8`.**
- [x] **W-6 (P1)** `GET /m/state` triggers a broadcast on every successful **read** (`match_play_response` does `changes.send(code)` — `main.rs:749-800`), fanning out WS re-fetches to both clients. Worse: WS push and REST poll both call `snapshot_for`, which **destructively advances the per-seat event cursor** (`drain_events`, `lib.rs:1079-1089`) — a client mixing both silently loses event-log lines. Fix: only broadcast on mutation; make event delivery idempotent (cursor-parameter or ack-based). — **done 2026-08-04, `df2d0ac8`.**
- [x] **W-7 (P1)** `FirstPlayer::Random` is a stub: it only perturbs the shuffle seed; **seat 0 always gets the play** (`lib.rs:933-935`, admitted at `lib.rs:906-909`). Fix properly (it changes game balance). — **done 2026-08-04, `df2d0ac8`.**
- [x] **W-8 (P1)** `/art/warm-all` is not behind `guard_local_only` (solo routes are, `main.rs:1334-1344`; art routes aren't, `main.rs:1375-1378`): any LAN peer can trigger ~8k Scryfall fetches (12–15 min, unbounded disk). Also `ensure_bulk` slurps the whole Scryfall bulk JSON into memory in one `bytes()` call (`main.rs:315-326`). — **done 2026-08-04, `df2d0ac8`.**
- [ ] **W-9 (P2)** Zero tests on the HTTP layer: `main.rs` (1,419 lines — every handler, ArtCache, WS loop, reaper, plus the `AutoPassRequest` string mapping duplicated at `main.rs:852-859` and `main.rs:1145-1153`) has none; the 27 existing tests cover lib/matchmaking well. The 5,350-line frontend also has none.
- [ ] **W-10 (P2)** Frontend/deck-store architecture: `static/index.html` is a 2,560-line monolith embedded via `include_str!` (`main.rs:73-81`); the "versioned lineage-aware deck store" lives entirely in browser localStorage (`static/app.js:386-439`) — decks don't roam and a cleared profile deletes them. `drawTargetingArrows` is a no-op placeholder (`static/index.html:2178`). `SeatSpec::Network` is a declared-but-rejected stub (`lib.rs:784-792`), leaving two parallel multiplayer models in the config type. Addressed properly in Phase 2 (server-side deck store + visual overhaul).

## C — arcana-core / arcana-session (engine)

- [x] **C-1 (P0)** `Effect::retargeted` (`arcana-core/src/effects.rs:1075`) and `Effect::for_player` (`effects.rs:1102`) whitelist ~10–17 of the **119 `Effect` variants** and end in silent `_ => {}` passthrough. This exact shape caused the ForEach bug (~294 cards silently no-op'd). Every new targeted/per-player variant must be hand-added or it silently misbehaves. Fix: make the matches exhaustive (compile error on new variants), or add a test that asserts every target-/player-bearing variant is covered. — **done 2026-08-04, `48cccd2e`.**
- [ ] **C-2 (P1)** `GameState` is non-serializable: 15 `TODO(serialize)` fn-pointer sites (index at `state.rs:46`; also `targets.rs:258,557`, `replacement.rs:92,343`, `layers.rs:142,1077`, `triggers.rs:99,229,953`, `effects.rs:54,2400`, `stack.rs:448`, `actions.rs:717`). Blocks true save/restore, networked resume beyond transcript-replay, and RL checkpointing. Fix: the `ConditionFnId` migration (registry of named fns instead of bare pointers). **This is the Phase 2 keystone.**
- [~] **C-3 (P1)** No `try_step`: `engine::step` (`engine.rs:113`) and `GameSession::apply` (`arcana-session/src/session.rs:108`) do no legality validation — any off-list action panics the process (policy: "panic = programmer bug", `engine.rs:2334`). Settle-loop panics (`engine.rs:2344, 2455`) convert one bad card script into a dead hosted server. arcana-web is currently safe only because it applies actions by index into the cached legal list (`arcana-web/src/lib.rs:1139-1148`). Fix: a fallible boundary (`try_step`) and/or panic containment per match (see W-3).
- [ ] **C-4 (P1)** RL/self-play hot-path tax: `Session::apply` deep-clones the entire `GameState` per action (plus a second clone with history on, `session.rs:117`) and `GameState::event_log` is an unbounded `Vec<GameEvent>` never trimmed (`state.rs:110`) — per-action cost grows with game length.
- [ ] **C-5 (P2)** `GameSession::undo` (`session.rs:134-151`) always synthesizes a `DecisionContext::Priority` yield after restore, wrong if the restored state was pending a resolution choice or combat declaration (acknowledged in-comment).
- [ ] **C-6 (P2)** Continuous-effect layers are timestamp-only; CR 613.8 dependency ordering unimplemented (`layers.rs:1890`) — known-wrong results for dependent layer interactions (type-changing + P/T-setting combos).
- [ ] **C-7 (P2)** `PlayerAgent::Human` panics unconditionally on `request_decision` (`arcana-session/src/agent.rs:74`) — documented placeholder, but a constructible public variant.
- [x] **C-8 (P2)** Stale comment: `legal_actions.rs:1123` claims blocking ignores evasion, but the per-pairing filter at `legal_actions.rs:1083-1093` handles Flying/Reach/Protection/Fear/Intimidate/Shadow/Horsemanship/Skulk. **Landwalk genuinely missing.** Fix the comment; implement landwalk or GAP it. — **done 2026-08-04, `5d15ceac`.**
- [ ] **C-9 (P2)** `let _ = move_object_to_zone(...)` drops the returned `new_id` (`effects.rs:4048`, `engine.rs:1535`) — benign at those sites (hand-bound), but this is exactly the CR 400.7 ETB-fidelity bug class; worth a lint/comment convention.
- [ ] **C-10 (P2)** Structure: `effects.rs` is 8,045 lines mixing enum + interpreter + cascade + token specs + five near-identical `push_*_choice` helpers (`effects.rs:4409-4551`); `legal_priority_actions` is ~835 lines (`legal_actions.rs:1137`). Refactor opportunistically, not as a project.
